# 开发指南

## 1. 开发环境

项目统一使用 Node.js `26.13.1` LTS 和 npm `11.20.0`。Windows NVM 用户在项目目录外执行：

```bat
nvm use 26.13.1
node -v
npm -v
```

如 Node 与 npm 版本不匹配，检查 `where node` 和 `where npm`，确认命令解析到同一套 NVM 安装目录。

## 2. Windows 本地启动

在项目根目录的 CMD 中依次执行：

```bat
copy .env.example .env
npm install
docker compose up -d postgres
npm run db:generate
npm run db:migrate -- --name init
npm run db:seed
npm run dev:api
```

另开一个 CMD 编译小程序：

```bat
npm run dev:mini
```

微信开发者工具导入 `apps/miniprogram/dist`。

## 3. Workspace 依赖说明

- API（NestJS 12）：TypeScript `6.0.3`，满足 `@nestjs/schematics` 12 的 TypeScript 6 peer dependency。
- 小程序（Taro 4.3.x）：TypeScript `5.9.3`，维持独立工具链版本。
- 两个 workspace 都使用 `@types/node` `26.6.6`，并不意味着它们必须使用同一 TypeScript 版本；该类型包包含 TS 5.9 与 TS 6 的兼容类型标签。
- 不要用 `--force` 或 `--legacy-peer-deps` 绕过依赖冲突。

如果此前安装失败，先关闭正在运行的 dev server，再在项目根目录 CMD 清理残留：

```bat
rd /s /q node_modules
del /f /q package-lock.json
npm install
```

如果 `node_modules` 或 `package-lock.json` 不存在，对应删除命令报错可以忽略。

## 4. Prisma 7

项目使用 Prisma 7 的 `prisma-client` generator，客户端生成到 `apps/api/src/generated/prisma`。该目录属于生成文件，已加入 `.gitignore`。下面命令会生成客户端：

```bat
npm run db:generate
```

API 的 `prestart:dev` 和 `prebuild` 生命周期也会自动执行生成命令。修改 `schema.prisma` 后，先生成客户端，再创建迁移：

```bat
npm run db:generate
npm run db:migrate -- --name describe_your_change
```

数据库连接地址放在项目根目录 `.env` 的 `DATABASE_URL` 中。Prisma CLI 配置位于 `apps/api/prisma.config.ts`，连接信息从环境变量读取。

## 5. 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev:mini` | 小程序开发编译 |
| `npm run build:mini` | 小程序生产编译 |
| `npm run dev:api` | 后端热更新开发 |
| `npm run build:api` | 后端生产构建 |
| `npm run build` | 构建 API 和小程序 |
| `npm run db:generate` | 生成 Prisma Client |
| `npm run db:migrate -- --name init` | 创建并应用数据库迁移 |
| `npm run db:seed` | 初始化演示数据 |
| `npm run db:studio` | 打开 Prisma Studio |

## 6. 微信小程序配置

- 修改 `apps/miniprogram/project.config.json` 的 `appid`。
- 真实微信登录需要在服务端设置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`，通过微信 `jscode2session` 校验 code。
- 小程序端 API 地址必须是可访问的 HTTPS 域名，并配置到微信公众平台 request 合法域名；本地开发可按开发者工具设置放宽校验。
- 订阅消息需要在公众平台配置模板，并在用户操作上下文申请授权；不可静默绕过授权。

## 7. 模块边界

- `inventory`：食材库存与数量。
- `recipes`：菜谱、配料、制作步骤。
- `recommendations`：匹配算法、每日推荐批次。
- `notifications`：通知偏好、后续接入订阅消息 Provider 和日志。
- `auth`：微信身份认证和服务端会话。
- `common/prisma`：数据库连接和生命周期。

推荐算法应保持纯函数或独立领域服务，UI 层不要维护与服务端不一致的排序规则。

## 8. 生产部署前检查

- 替换 JWT Secret、数据库密码和微信密钥。
- 生产环境只允许 HTTPS 和已备案/已配置的小程序合法域名。
- 为所有库存、菜谱、历史、推荐接口验证 household membership。
- 配置数据库备份、日志脱敏、速率限制和异常监控。
- 配置微信 request 合法域名及订阅消息模板。
- 验证用户隐私协议、个人信息处理规则与平台审核要求。
